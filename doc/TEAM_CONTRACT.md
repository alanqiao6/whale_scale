
# Team Contract

---

## **Team Name**: Whale Scale  

---

## **Team Procedures**

1. **Regular Meeting Time**:  
   - **Day**: Tuesday  
   - **Time**: 1:30 PM - 3:00 PM  
   - **Location**: TBD (In-person or virtual as required)  

2. **Preferred Communication Methods**:  
   - Text messages  
   - Zoom for virtual meetings  
   - In-person discussions if necessary  

3. **Decision-Making Policy**:  
   - Decisions made by consensus whenever possible  
   - If consensus is not achievable, majority vote will decide  

4. **Task Assignment and Deadlines**:  
   - Use GitHub Issues to manage and track tasks  
   - Team members can claim issues by assigning themselves  
   - Deadlines set during weekly meetings  

5. **Requesting Help or Extensions**:  
   - Communicate early (minimum 48 hours in advance) if help or an extension is needed  
   - Text channel to discuss workload and assistance  

6. **Meeting Agenda Management**:  
   - Use a shared document for agendas  
   - Team members can add agenda items before meetings  
   - Scrum Master ensures adherence to the agenda  
   - Meeting reminders sent via text  

7. **Record Keeping**:  
   - Rotate meeting note-taking responsibilities  
   - Notes shared with the team post-meeting  
   - All documentation stored in a shared team folder  

8. **Code Ownership and Modification**:  
   - Collective code ownership after merge into protected branches  
   - Feature branch creators own code until it is merged  
   - API changes require prior approval and documentation  
   - Git feature branches used with code reviews before merging  

---

## **Team Expectations**

1. **Project Standards**:  
   - Aim for professional-quality work to achieve an **A** grade  
   - Rigorous adherence to pre-requisite skills and high standards  

2. **Weekly Time Commitment**:  
   - 5-10 hours per week outside of class  

3. **Quality Disputes**:  
   - Discuss concerns in team meetings  
   - Align expectations and review work collaboratively  

4. **Work Habits**:  
   - Follow a predefined schedule to accommodate diverse working styles  
   - Weekly standups to maintain consistent progress  

5. **Differing Goals**:  
   - Workload adjusted for differing grade goals (e.g., A vs. B)  
   - Reflected in evaluations  

6. **Additional Workload Contributions**:  
   - Members contributing extra effort will be recognized in evaluations  

---

## **Personal Accountability**

1. **Attendance and Participation**:  
   - Attend all meetings on time unless prior notice of conflict  

2. **Responsibility for Deadlines**:  
   - Shared accountability for meeting deadlines and commitments  

3. **Communication Standards**:  
   - Use text channel for updates  
   - Executive decisions allowed only when not affecting agreed API structure  

4. **Team Decision Participation**:  
   - Equal voting rights during meetings  
   - Absent members can vote over text if responsive  

5. **Infractions Management**:  
   - Address issues with team meetings or “war room” coding sessions  
   - Escalate unresolved issues to Professor Duvall  

6. **Serious Infractions**:  
   - Notify Professor Duvall if a member fails to communicate or contribute during a sprint  

7. **Member Removal**:  
   - Request removal if a team member repeatedly fails to meet commitments or communicate  

---

## **Team-Specific Agreements**

- Respect all team members’ ideas and contributions  
- Maintain open communication to keep everyone informed  
- Add additional agreements based on team discussions
